Preview stages

Revision 1's preview was a drawing made for two tiles. A preview needs a real scene, and hand-building one per effect wouldn't scale. So a preview is a stage: a small room grid, a target cell, and an optional actor clip, played through the same replay-mode Game that rewatches player sessions (src/game/replay.ts). Falls really flow, the actor really bounces, and effects fire from the real events at their real timing.

One stage per kind of moment

Stages live in vfx.json next to the presets, and each moment names a default: "Bounced on" uses Drop onto it, "Meets a pool" uses Fall into a basin. The studio puts the tile being previewed into the stage's @ cells. About six stages cover every moment, and a new tile gets working previews with no setup at all.

Three ways to change it

A real spot: pick any place the tile actually appears (the level filter already knows them), and the preview runs that room around that cell. A custom stage: paint a grid, record the actor by playing a few seconds, save it for this tile or as a new shared stage. ⚡ Fire now: skip the event for fast slider work, labelled as a shortcut.

What the runner does, in order

  1. Builds a one-room content bundle from the draft: the stage map with @ replaced by this tile's char, and the draft's tiles, entities and effects.
  2. Starts a replay-mode Game on it, feeds the clip by step, and loops after seconds. For a real spot it loads the actual room and frames the camera on the cell.
  3. Draws through the real renderer into the stage canvas, culled to the camera, and stops whenever the panel re-renders (live sync, navigation), the way the Environments preview does.
  4. Counts the moment events it saw. Zero after a full loop flags the stage as broken, in the panel and in CI.

Service map

Effects follow the same path as art: authored in the studio, stored in content/, published through the art scope, read by the game. The firm line is the sim wall: nothing on the right of it can change a run, which keeps session replays exact.

What gets stored

All artist-owned. A shared library of presets, game-wide defaults and stages, plus a short list on each tile or placeable item. Per-tile values sit on top of the preset, the same model as behavior attachments, so a tweak never forks the preset.

content/vfx.json (new, wholly artist-owned like layers.json)

{
  "presets": [
    { "id": "splash", "name": "Splash",
      "layers": [ { "id": "drops", "kind": "particles",
        "count": 14, "cone": 70, "dir": -90,
        "speed": 90, "gravity": 320, "life": 0.45,
        "size": [3, 1],
        "colors": ["#e6f7ff", "#4fc3f7"],
        "shape": "round", "blend": "normal" } ] },
    { "id": "squish", "name": "Squish",
      "layers": [ { "id": "squash", "kind": "tween",
        "target": "tile", "ms": 260, "anchor": "bottom",
        "scaleY": [[0, 1], [0.25, 0.55],
                   [0.6, 1.15], [1, 1]] } ] }
  ],
  "defaults": {
    "ignite":  [ { "preset": "builtin_ignite" } ],
    "shatter": [ { "preset": "builtin_shatter" } ],
    "bounce":  [ { "preset": "builtin_spring" } ]
  },
  "stages": [ … ]
}

Bindings on a tile or placeable item (new art field vfx)

{ "id": "waterfall", …,
  "vfx": [
    { "id": "splash", "on": "fallImpact:fluid",
      "preset": "splash",
      "params": { "drops": { "count": 10,
                             "speed": 70 } } },
    { "id": "mist", "on": "fallImpact:fluid",
      "preset": "mist", "while": true }
  ] }

{ "id": "spring", "char": "S", …,
  "vfx": [
    { "id": "squish", "on": "bounce",
      "preset": "squish", "mode": "add" }
  ],
  "vfxStage": { "bounce": "drop_onto" } }

mode: "add" plays on top of the game-wide default; "replace" silences it for this tile. params are keyed by the preset's layer ids, so per-tile values survive the preset being reordered. while streams for as long as the moment keeps happening (a fall lands every flow tick).

Action plan for the agent

Seven phases, each shippable on its own and each ending green. Invisible, test-pinned work comes first, so the panel lands on a model that's already proven.

Phase 1

Schema, defaults, and moving the built-ins out of code

Risk: low · no visible change
  • types.ts: VfxLayer (particles · tween · glow · shake · flash, each with an id), VfxPreset, VfxBinding { id, on, preset, params?, mode?, while? }, VfxStage; vfx? on TileDef and ItemDef.
  • content/vfx.json: a builtin_* preset and a defaults entry for every hardcoded particles.burst in game.ts (element effects, land dust, tile bounce, placed spring), values copied exactly.
  • content.ts: assemble vfx.json; add vfx and vfxStage to ART_KEYS so a removed binding stays removed.
  • Tests first, tests/vfx-model.test.ts: preset resolution, per-layer params, add/replace over defaults, used-by counts, and parity of each built-in with the old literals.

Done when the game looks identical and parity passes.

Phase 2

Moment events and the resolver

Risk: medium · touches room.ts and game.ts event paths
  • Element events in room.ts gain tileId (the tile before the change). A cosmetic field; no sim code reads it.
  • New cosmetic events: fallImpact:fluid|solid in tickFalls, fluid enter/exit from player overlap. Placed-spring bounce raises bounce with the item id.
  • tileMoments(content, id), a pure function over the engine's own parseRuleLine plus tile and item fields.
  • Tests: tests/vfx-moments.test.ts drives small rooms headlessly and asserts each moment tileMoments lists is really raised, and nothing it omits is. tests/vfx-determinism.test.ts asserts identical sim state per step with effects on and off. The fluids suite stays green.

Done when every event names its tile and a recorded session still replays with 0 px drift.

Phase 3

VfxPlayer

Risk: medium · replaces the particle path
  • src/engine/vfx.ts: resolves defaults plus bindings for an event and plays them. Particles gain shape, color ramp, size curve, cone and direction, additive blend, sprite particles (SpriteFields), and an enforced 600 cap that drops the oldest.
  • Tile tweens: a per-cell transform map read by drawTile, timed on animT like parallax, so replays stay pixel-identical.
  • Screen layers reuse camera.shake; a flash capped at 3 per second. All honor the juice toggles. Hit-stop and sound stay in code and are reported to the panel as locked rows.
  • Switch every game.ts burst over to the player.

Done when the game still looks identical, now driven entirely from vfx.json.

Phase 4

Publish scope and merge

Risk: low · pinned by existing suites
  • _artscope.js: vfx, vfxStage into SPRITE_FIELDS; vfx.json into ART_OWNED_FILES.
  • Bindings and layers carry ids, so _merge.js merges them per item unchanged. Add a collab-publish.test.ts case: two artists editing different presets, and one conflict on the same preset field.
  • artist-publish.test.ts: an artist can publish vfx, can't touch bounce, fallSpawns or hit-stop.
Phase 5

Stage runner

Risk: medium · new, but built on replay mode
  • src/studio/stage.ts: builds a one-room bundle from a stage and the draft, runs a replay-mode Game with the clip, loops, counts moment events, culls to camera, stops on re-render.
  • Real spots from assetLevels: load the actual room, frame the cell.
  • Painter reusing the room editor's paint tools; clip recording through Input.onTransition, as the session recorder does.
  • Default stages for every moment kind, plus tests/vfx-stages.test.ts: each default stage, with a representative tile, raises its moment within seconds.

Done when every default stage passes in CI and a broken custom stage refuses to save.

Phase 6

The Effects panel

Risk: medium · biggest UI surface
  • src/studio/effects.ts: This tile / Every tile scope, moments from tileMoments, effect stack with locked rows, inspector with per-tile overrides and a separate "edit shared preset" mode, draggable keyframe curve, used-by counts, worst-case meter from real rooms, the Spring twin row.
  • Mount on tile and placeable-item pages, and in the editor through TILE_SCHEMA and ITEM_SCHEMA.
  • Saves go through store.saveFile, so live sync, the busy guard and the board work unchanged. Conflict dialog labels vfx.json#preset groups and renders effect values as a table.

Done when an artist builds the mist effect from the journey without help, verified in the browser pane.

Phase 7

First-pass effects, docs, ship

Risk: low · content and docs
  • Waterfall: Splash plus a light Mist stream on fallImpact:fluid. Lavafall: additive Embers. Bounce Pad and placed Spring: Squish (scaleY 1 → 0.55 → 1.15 → 1 over 260 ms, anchored at the base) added on top of the default burst.
  • All ordinary presets in vfx.json, so Casey can open, tweak or delete each one. Captured in Greenhouse, The Vault and The Gap with PP.capture().
  • ARTIST_HANDOFF.md "Effects" section; CLAUDE.md: sim wall, moments table, the stage check. Local two-artist run, content:pull, deploy, provenance commit.

Decisions for Sean

Can artists add screen shake and flash?

Both are looks. Hit-stop pauses the sim for a beat, which is feel, so it shows as a locked row either way.

Recommended: shake and flash in the artist scope with hard caps; hit-stop and sound stay yours.
Tiles and placeable items only, or entities too?

Brazier and checkpoint are the obvious next ask. The model is the same; entities add moments like "lit" and "activated".

Recommended: tiles and placeable items this round; entities next, as new moments rather than new machinery.
A "reduce flashing" setting for players?

Artist-made flashes raise the photosensitivity question before Steam.

Recommended: yes, beside the screen-shake toggle, with the 3-per-second cap regardless.
Sound in the panel later?

Sounds are WebAudio synth patches in audio.ts, so the same preset model could cover them, but that's a sound designer's tool, not an artist's.

Recommended: leave sound as locked rows for now; revisit when someone owns audio.
