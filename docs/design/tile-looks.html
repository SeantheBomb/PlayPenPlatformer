Tile Looks by Placement

Looks live inside the asset page you already use. A strip of looks sits at the top of the art editor: the main art, the built-in looks, and any the artist adds. Pick a look and the whole page edits that look: its art, its frames, and when it shows. It works the same for tiles, objects, and the placed Spring.

What's true today

Built-in looks are code-only

drawMap passes capped (deep water and lava, looking up through grates) and gooNeighbors (floor, wall, ceiling). Only the built-in drawings use them.

Custom art switches them off

drawTile draws the sprite and returns early. Water, lava and both falls have 16-frame art, so every cell of a pool looks the same right now.

Objects have one extra slot

spriteAlt is a single still for the second state (open door, unlit brazier). It can't animate and can't depend on where the object sits.

How a look decides

  • First look that fits wins, left to right in the strip, the same as rules.json. Main is pinned first in the strip but checked last: it's "everywhere else".
  • 3×3 around the tile: 8 optional neighbour squares around the tile itself. Each accepts any of This tile · Not this tile · Empty · Solid · Not solid · Any fluid, plus specific tiles by id. A square left at Anything isn't checked.
  • Off the room edge = Empty.
  • Look through grates, per look: a grate counts as whatever is past it. The built-in deep looks have it on, matching today.
  • No art yet ⇒ falls through to the next look that fits, then the main art, then the game's built-in drawing. An empty look never changes what players see.
  • Built-in looks (deep water and lava, goo on wall or ceiling, object states) show in the strip with a "built-in" badge. They can be reordered, edited, switched off, and restored.
  • One clock, one pattern. Looks animate on the asset's own clock and use the tile's world-aligned pattern, so seams line up. A look whose frame count differs from a neighbour it touches gets a warning.
  • Up to 8 looks plus the main art.

Objects

State looks join the strip

An object's state (open, unlit, tripped, occupied, active, live) becomes one more condition on a look, shown as a row of chips above the grid: Any state · Lit · Unlit. The old second-look slot becomes the built-in "Unlit" look. Its existing art (spriteAlt) is read as that look's art, so nothing needs migrating and nothing an artist made is lost. It can now animate, too.

Neighbours around a footprint

Objects aren't on the tile grid, so their squares mean the tiles touching the footprint's edges. "Below" is satisfied when every cell along the bottom edge fits; a corner is the single diagonal cell. A one-tile brazier reads like a tile, and a two-tall door checks both cells beside it. The resolver uses the object's live position and state each draw, so a placed Spring dropped on a grate picks its look right away.

What gets stored

A tile: the art field looks (only once an artist touches it)

{ "id": "water", "spriteFrames": ["…main art…"],
  "looks": [
    { "id": "under_fall", "name": "Under the waterfall",
      "when": { "up": { "tiles": ["waterfall"] } },
      "spriteFrames": ["…"], "spriteFps": 10 },
    { "id": "deep", "name": "Deep water", "builtin": "deep",
      "throughGrates": true,
      "when": { "up": { "is": ["self", "solid"] } } }
  ] }

An object: state plus placement

{ "id": "brazier", "sprite": "…lit…",
  "looks": [
    { "id": "unlit_wall", "name": "Unlit on a wall",
      "when": { "state": "alt",
                "left": { "is": ["solid"] } },
      "sprite": "…" },
    { "id": "unlit", "name": "Unlit", "builtin": "alt",
      "when": { "state": "alt" } }
  ] }
// up · down · left · right · upLeft · upRight · downLeft · downRight
// is: self | notSelf | empty | solid | notSolid | fluid
// tiles: [ids]  ·  absent square = Anything
// state: "alt" (open / unlit / tripped / …) | "main"

Action plan for the agent

Phase 1

Model, resolver, built-in parity

Risk: low · no visible change
  • types.ts: Look extends SpriteFields { id, name, when, throughGrates?, builtin? }, with looks? on TileDef, EntityTypeDef and ItemDef.
  • src/engine/looks.ts: lookFor(map, cell | footprint, def, state?), first match, off-map = empty; builtinLooks(def) for anything with no looks key; shadowedBy().
  • drawMap and drawEntitySprite use the resolved look; capped/gooNeighbors/spriteAlt become what the built-in looks select.
  • tests/looks.test.ts: parity with the old code on every cell of every shipped room; footprint rule; first match; shadowing; off-map.

Done when captures of Greenhouse, The Vault and Mess Hall are pixel-identical before and after.

Phase 2

Art per look in the renderer

Risk: low
  • Fall-through chain; pattern alignment; shared clock; the grate-fluid overlay path; placed items. Tests for each.
Phase 3

Content, publish, merge

Risk: low · pinned by existing suites
  • SPRITE_FIELDS += "looks"; absent ⇒ built-ins; [] ⇒ none; spriteAlt read as the built-in state look. Conflict labels and preview per look. Tests extend artist-publish, collab-publish and content-art-merge.
Phase 4

The look strip on the asset page

Risk: medium · reworks the detail view
  • studio.ts detailView: the strip above the art; selecting a look retargets zooms, frames, drop zone, import, pixel/shape editors, speed and Aseprite. A "When this look shows" card holds the state chips, the 3×3, the sentence and the grates toggle. altSlot is removed.
  • Room preview per level with look tint and counts, plus live sim via StageRunner. Suggestions from data. Warnings on the tabs.
  • Gallery "N of M looks drawn"; board cards per look; the editor's sprite panel gets the same strip.

Done when the water and brazier journeys work end to end in the browser pane, and the Effects card still sits below the art.

Phase 5

Aseprite tags to looks

Risk: low
  • One file fills every look whose name matches a tag; reimport loop; unmatched tags listed. Extend aseprite.test.ts.
Phase 6

Docs and ship

Risk: low · no content changes
  • ARTIST_HANDOFF "Looks" section; CLAUDE.md notes. Deploy code only. No looks are added to content, so players see no change.

Open questions

Should Effects move into the same strip?

Effects is already a card on this same page, below the art. It could become per-look (squish only on the deep look), but that's a bigger change.

Recommended: leave Effects as the card below the art for now.

NPC bodies, enemies, the player?

They move every frame, so where they're standing changes all the time.

Recommended: out of scope; their art stays as it is.
